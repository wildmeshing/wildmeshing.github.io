    /throw_on_nonconvergence

    Description

    /optimize_offset (bool) 

    /optimize_offset

    Description

    Run the optimization (optimize_offset: pre-loop setup, the loop’s turns, the final pass and the convergence verdict) after the offset is constructed. Default true. false: the run stops at the constructed offset – the simplicial embedding, the marching and the tag assignment still run – and writes it as the result.     /envelope_size (float) 

    /envelope_size

    Description

    Absolute half-width of the envelope that holds the held surfaces (see envelope_size_rel). If <= 0 (the default -1): derived from envelope_size_rel.

    Default: -1.0

    /envelope_size_rel (float) 

    /envelope_size_rel

    Description

    Half-width, relative to the bounding box diagonal, of the envelope that holds the held surfaces during optimization; any operation that would push a held face outside it is rejected, and a held vertex is smoothed toward it. 3D: ONE envelope around every held face, built after the simplicial embedding, before the repulsion and the march: during the loop the domain wall and the input complex’s boundary; in the frozen-front final pass every other region boundary as well, at its position as the loop left it (see use_rest_pose). The offset surface is never in it. 2D: one tube per region tag, as before. Ignored if envelope_size > 0.

    Default: 0.001

    /offset_field (string) 

    /offset_field

    Description

    Which field defines the offset, and so what the front is placed on, what the criterion measures and what the sizing field refines by. ‘smooth’ is the offset geometric contact potential Phi, with the front on the level set Phi = c: C^2, analytic derivatives, and a level set that bulges outward at reentrant features, so it is a smoothed offset rather than the exact one. ‘euclidean’ (the default) is the exact distance to the input complex, which makes the residual exact but introduces a gradient discontinuity across the medial axis and a crease at every reentrant feature that no refinement resolves; offset_dhat_factor and the outside-the-support guard stop meaning anything, since it has no compact support. 3D refuses ‘smooth’ with an error at startup: the 3D energy’s band term reads the euclidean distance, and the smooth field has no band term; ‘smooth’ is 2D only.

    Default: 'euclidean'

    Options: ['smooth', 'euclidean']

    /offset_dhat_factor (float) 

    /offset_dhat_factor

    Description

    Support radius of the smooth offset potential, as a multiple of target_distance. Must be > 1. The offset level set lies strictly inside the support; a band vertex that leaves the support is a hard error.

    Default: 2.0

    /front_conv (float) 

    /front_conv

    Description

    THE convergence epsilon, as an ABSOLUTE length in model units; <= 0 (the default -1): derived from front_conv_rel. Absolute-or-relative exactly as envelope_size / envelope_size_rel, and against the same reference, the bounding box diagonal – deliberately NOT a fraction of target_distance, so changing the offset distance no longer silently changes the accuracy. Startup refuses a value above target_distance: an epsilon coarser than the offset it measures decides nothing, since every front face then reads as resolved from the first turn. THIS IS THE ONLY BAR, in 2D and 3D. The measure it gates is one quantity everywhere: over a face’s stencil_order stencil (in 2D a front chord’s), the ROOT MEAN SQUARE of the distance to the level set along the field, over target_distance (for ‘euclidean’ the relative error (Phi - c)/c = (d - target_distance)/target_distance; for ‘smooth’ the root of Phi = c along grad Phi, since there (Phi - c)/c is not a length and read 3.44x the distance error at offset_dhat_factor 2), taken as a length. A face is resolved when that RMS is <= front_conv, i.e. when the MEAN SQUARED relative error is <= (front_conv/target_distance)^2; a vertex is placed when the same measure at the vertex alone – the order-0 stencil – is within it. So the vertex measure and the face measure are ONE measure at two sample counts, which is why vertex_conv and sag_conv, which split them apart on 2026-09-23, no longer exist. The offset surface debug field f_err reports the same number. The 2D front smoothing objective (StencilEnergy2D) has the same zero set but, under ‘smooth’, charges the field error (Phi - c)/c rather than this distance: about 3.44x it at offset_dhat_factor 2. The 3D smoothing objective is the energy (see offset_amips_weight), which has no face term. WHAT THE LOOP EXITS ON is set by front_measure: under the default ‘vertex_ring’, every front vertex’s ring measure (the RMS of its offset faces’ measures, every face weighted equally) within the bar; under ‘face’, the rule of 2026-09-25, every offset face’s measure within the bar. Either way nothing may be unmeasurable, the single-point vertex measure is a diagnostic that decides nothing about termination, and an element over the bar that refinement cannot take (the sizing floor) blocks the exit and is named in a warning every turn it exists. 2D runs the same criterion on its front chords (offset edges in place of offset faces).

    Default: -1.0

    /front_conv_rel (float) 

    /front_conv_rel

    Description

    THE convergence epsilon as a fraction of the BOUNDING BOX DIAGONAL, used when front_conv is <= 0; ignored if front_conv > 0. The default 2.5e-4 is the old front_conv_rel default 0.025 times the default target_distance_rel 0.01, so a fully default run keeps the accuracy it has always had; at any other target_distance the default accuracy now differs from the pre-2026-09-23 behaviour, which is the point of referencing the box rather than the offset. See front_conv for what the bar actually gates.

    Default: 0.00025

    /stencil_order (int) 

    /stencil_order

    Description

    Order of the sampling stencil on an offset-surface face (3D) or front chord (2D). It sets the convergence measure, and in 2D also the front smoothing energy, which samples the same points; the 3D energy has no face term (see offset_amips_weight). Order 0 is the 3 CORNERS alone, so the measure is exactly the three vertices’ own placement error. Order k >= 1 is the vertices of the triangle subdivided k-1 times by 4-way midpoint refinement, plus the centroid of each of its 4^(k-1) sub-triangles: with n = 2^(k-1) segments per side that is (n+1)(n+2)/2 + n^2 points, i.e. 4 at order 1 (the corners and the centroid), 10 at order 2 (the corners, the 3 edge midpoints and the 4 sub-triangle centroids), 31 at order 3, 109 at order 4. On a 2D chord the same rule one dimension down: order 0 is the 2 ENDS alone, order k >= 1 the vertices of the chord cut into 2^(k-1) pieces plus the midpoint of each piece, i.e. 3, 5, 9, 17 points. THE CORNERS ARE IN THE STENCIL, unlike the strictly interior lattice sag_num_samples used, and they have to be: the quantity sampled is a distance to the level set, which at a corner is that vertex’s own placement error rather than the identically-zero interpolation error the old measure saw there. That is what lets one stencil replace the separate vertex and sag criteria. COST: every sample is a Phi value, paid in the criterion and the frames, and in 2D also in the operations’ energy rules (TopoOffsetTriMesh::tri_energy()) and, with a gradient, in every front solve – 4 points at the default against 6 for the old default.

    Default: 1

    Range: [0, inf]

    /front_measure (string) 

    /front_measure

    Description

    Which measure the loop exits on and refines by, in 3D and in 2D. ‘vertex_ring’ (the default): at each front vertex v the RING MEASURE r_v = sqrt((1/n_v) sum_f m_f^2), over the n_v offset faces f incident to v whose three corners are front vertices, every face weighted equally, m_f the face measure, the root of face_offset_term() (the RMS over the face’s stencil_order stencil of the distance to the level set along the field over target_distance – for ‘euclidean’ the relative error (Phi - c)/c – over the bar front_conv / target_distance). The loop exits when every ring measure is within the bar and nothing is unmeasurable; a vertex with an unmeasurable incident face has no ring measure and blocks the exit. The face and vertex measures are then reported as diagnostics. The halving lowers the sizing scalar at each vertex whose ring measure is over the bar, that vertex alone, under the same floor (max of min_sizing_scalar and min_edge_length / l); a vertex over the bar already at the floor blocks the exit and is named by the [sizing floor] warning. The chord rule is not read in this mode. The operations do not compare this measure (until 2026-09-28 an ops guard compared the ring measure before against after): in 3D the collapse, the swaps and the smoother compare the energy (TopoOffsetTetMesh::tet_energy(), see offset_amips_weight), whose band term is a volume integral of the distance error, not these face measures. From 2026-09-25 to 2026-09-28 this measure weighted each face by its area (A_f); it weights every face equally since. In 2D the same criterion runs on the front chords: r_v = sqrt((1/n_v) sum_e m_e^2) over the n_v front chords e incident to v, m_e the chord measure (the root of edge_offset_term()), every chord weighted equally, with the same exit and the same per-vertex halving; 2D’s operations compare the per-cell energy TopoOffsetTriMesh::tri_energy() and its front smoother minimises StencilEnergy2D, the same chords’ m_e^2. ‘face’: the rule of 2026-09-25, kept for comparison. The loop exits when every offset face’s (2D: chord’s) measure is within the bar and nothing is unmeasurable; the halving lowers the sizing scalar at the corners of every face over the bar whose chord rule still has a target below its corners’ scalars. Why the ring measure: the smoother minimises a sum over each vertex’s ring while the face exit and refinement are per face, and the two disagree at the margin. Measured on the deliverable cube at target_distance_rel 1e-3 / front_conv_rel 1e-5 under ‘face’, turns 12-15: the loop never exits because a handful of faces end each turn at 1.00 to 1.19 times the bar, the smoothing having pushed faces from 0.99 to just over the bar while lowering the ring they belong to. On the cube at target_distance_rel 1e-2 / front_conv_rel 1e-4 (the split gate at twice the collapse gate, a key since removed, interleaved_smoothing false, 2 smoothing passes, no alignment term, serial), measured with the area weights and before the per-tet energy: ‘vertex_ring’ exits after 7 turns with max AMIPS 8.784 and 20724 front faces, 60 of them over the bar (the largest 1.355x) while every ring measure is within it (the largest 0.963x); ‘face’ exits after 7 turns with max AMIPS 7.814 and 23476 front faces. The debug frames carry the ring measure as point data, front_ring_ratio, in both modes (2D: on the _front.vtu chord mesh).

    Default: 'vertex_ring'

    Options: ['vertex_ring', 'face']

    /sorted_marching (bool) 

    /sorted_marching

    Description

    Execute the marching in decreasing order of edge length. Increases run time, may increase output mesh quality.

    Default: False

    /save_offset_correspondence (bool) 

    /save_offset_correspondence

    Description

    2D and 3D, and only with optimize_offset false (the run refuses the combination with true). The output .msh carries the node field corr_input_vid, a scalar $NodeData entry for every vertex of the mesh (the retained envelope’s own nodes, when the input has an EnvelopeSurface, carry none). The march splits every edge with exactly one endpoint on the input complex and so makes the offset vertices (vertex label 2, the vertices of the offset band that are not on the complex); for each such vertex the field holds the 0-based index of that edge’s endpoint on the complex, the input-complex vertex the offset vertex was split off from. Every other vertex holds -1. The index is the output file’s own: vertex k is the node with tag k + 1. The optimization splits, collapses and renumbers vertices and does not carry the field, hence the restriction. The prismatic_mesh component reads this file. Default false: the .msh has no node data.

    Default: False

    /construction_mode (string) 

    /construction_mode

    Description

    How the marching constructs the offset. Construction first measures the maximum marchable distance, the smallest distance from the input complex of the outer end of any marched edge (an edge with one end in the input complex and the other in the background). Every marched edge’s inner end is on the complex, so the level set d = D crosses every marched edge for every D up to that distance. If target_distance is below it, every marched edge is split where d(x) = target_distance, found by sphere tracing from the complex end (to within sphere_trace_target_rel_tol). Otherwise: ‘max_marchable_fallback’ (the default) traces every marched edge to half the maximum marchable distance instead; ‘midpoint_fallback’ splits every marched edge at its midpoint. Either way target_distance itself is not changed: the optimization carries the offset surface out to it. Both dimensions.

    Default: 'max_marchable_fallback'

    Options: ['max_marchable_fallback', 'midpoint_fallback']

    /sphere_trace_target_rel_tol (float) 

    /sphere_trace_target_rel_tol

    Description

    In (0, 1). The marching’s sphere trace stops at the first point where |d(x) - D| <= this x D, D being the distance the march traces to (target_distance, or half the maximum marchable distance under construction_mode max_marchable_fallback); the placed vertex is that close to that level set along the edge. Smaller is tighter and takes more steps (each step is longer than the tolerance, so at most edge length / (this x D) per edge).

    Default: 0.01

    /init_optimize (bool) 

    /init_optimize

    Description

    Default false, as the band-volume runs ran it. 2D and 3D. Construction measures the maximum marchable distance, the smallest distance from the input complex of the outer end of any marched edge (the largest target every marched edge can be traced to). If target_distance is below it, the init_optimize loop is not done: the offset is marched to the target and the loop runs with refinement as usual, and the log says so. If target_distance is not below it, every marched edge is split as construction_mode says (the default traces it to half the maximum marchable distance; midpoint_fallback splits it at its midpoint), the loop first converges under stencil_order with no refinement (the sizing field left as it is), without the final pass, and then the ordinary loop converges under the same stencil_order with its refinement, final pass and verdict. target_distance is never changed. The no-refinement loop’s debug frames are led by i.

    Default: False

    /repulsion_smoothing_passes (int) 

    /repulsion_smoothing_passes

    Description

    2D and 3D. At most this many smoothing passes between the simplicial embedding and the march, so that the march can trace to target_distance itself. The march traces every marched edge (one end in the input complex, the other not) to target_distance only if every outer end is farther than it (the maximum marchable distance, see construction_mode); otherwise it falls back. The repulsion vertices are those outer ends – the one ring of the input complex’s vertices minus the complex – that no input envelope holds. One per-cell energy holds before the march: the energy’s AMIPS term (3D: see offset_amips_weight; 2D: w AMIPS, the 2D engine’s quality, w = offset_amips_weight, as the front) plus, for each corner v of the cell (2D: face) that is a repulsion vertex joined in that cell to the input complex by a marched edge, O(v) = (max(0, 2 delta - d(v)) / front_conv)^2, delta = target_distance, d the Euclidean distance to the input complex. O is one-sided, so it pushes a vertex out and never pulls one in, and its target is 2 delta so that the march at delta splits each edge with room to spare (the construction’s own fallback, half the maximum marchable distance, run backwards). Every vertex is smoothed against the sum of that energy over its ring, so a repulsion vertex’s O(v) counts once for every ring cell that carries it; every other vertex is smoothed as in the loop. In 3D no move may raise the sum of the energy over the vertex’s ring; in 2D a repulsion move has no veto and every other vertex keeps the veto on the max of the energy over its ring. The passes stop as soon as every outer end is farther than delta + front_conv, i.e. outside the tolerance band. Each pass logs the maximum marchable distance, the outer ends within delta + front_conv, delta and 2 delta, and the max AMIPS; with debug_output a frame repulsion_ follows each pass. 0 (the default) = off: no pass, no frame, no log line.

    Default: 0

    Range: [0, inf]

    /repulsion_rounds (int) 

    /repulsion_rounds

    Description

    2D and 3D. After the repulsion_smoothing_passes (if any) and before the march, at most this many rounds of the loop’s operations: split, collapse and swap, each followed by its smoothing passes, shaped as interleaved_smoothing says. No refinement: the sizing field is never lowered, so every operation aims at the base edge length. No split of a marched edge (one end in the input complex): its midpoint would be a new outer end nearer the input. The collapses and swaps compare the per-tet energy of repulsion_smoothing_passes, repulsion terms included, as the loop’s rules compare its energy. The input complex stays simplicially embedded, as the march needs it: a collapse or swap that would leave a cell off the complex whose complex vertices span an edge or face off the complex is refused. After every operation pass the construction labels are recomputed from the region tags, and the repulsion vertices follow the operations. Single-body offset_in or offset_out only (the embedding test reads the complex off the cells’ labels); other selections, and in 2D a curve group, are refused with an error. The rounds stop as soon as every outer end is farther than target_distance + front_conv. Each round logs its operations’ outcomes ([ops accounting], [swap reject], 3D only: the 2D engine has neither; the embedding refusals, which those counters have no name for, are counted on the round’s own line), the maximum marchable distance and the max AMIPS; with debug_output a frame repulsion_round_ follows each round. The embedding test reads cells beyond an operation’s lock, so run the rounds with num_threads 0. 0 (the default) = off.

    Default: 0

    Range: [0, inf]

    /EXPERIMENTAL_split_energy_gate (bool) 

    /EXPERIMENTAL_split_energy_gate

    Description

    EXPERIMENTAL (2026-10-09), 3D. Every split of the optimisation loop (not the march’s) is committed only if the energy E, summed over the cells it changes – the parents before, the children after – strictly falls, judged right after the split and before any smoothing; otherwise it is rolled back. A split never raises the energy’s band term, so a split passes where the bound tightens by more than the AMIPS term rises (bisecting a well-shaped tet makes worse-shaped children), and is refused where the bound is already exact. Strict, since every split adds cells. What proposes splits is unchanged (the sizing field and its refinement). false (the default) = splits are not judged by the energy.

    Default: False

    /EXPERIMENTAL_band_volume_rule (string) 

    /EXPERIMENTAL_band_volume_rule

    Description

    EXPERIMENTAL (2026-10-12), 3D. The band term b(t) of a band cell in the energy (see offset_amips_weight; TopoOffsetTetMesh::band_cell_term()), the cell’s part of the integral over the band of (d - target_distance) / target_distance. “corner_bound” (the default): vol times the min, over all input triangles P, of the mean of (d_P - target_distance) / target_distance over the cell’s four corners, d_P the distance to triangle P alone: an upper bound on the cell’s part (d <= d_P, and the convex d_P lies below its linear interpolant) that no split raises (a child can use its parent’s minimiser, whose finer interpolant lies lower); exact where one triangle’s distance is affine on the cell. “exact”: J_t / target_distance, J_t = int_t (d - target_distance) dV in closed form (ExactBandIntegral, a C++ port of the Python reference exact_mesh.integrate_mesh): the cell is cut by the local regions of the input’s faces, edges and vertices into convex pieces on which d is one plane, line or point distance, each integrated exactly (Euler’s theorem for homogeneous integrands and the divergence theorem on the faces; two convergent series with explicit tail bounds for faces nearly parallel to an input edge, stopped at each edge’s own ratio). Where the border between two competing features’ regions is curved (a face and an edge, or an edge and a vertex, inside one piece: “rule (a)”) the piece takes the smaller of their integrals, an upper bound: 0.15-0.35% of the band volume on Thingi 100026, 0.01% on the cylinder, none on the cube and prism. The front smoother descends the same J with its exact gradient and Hessian in the moving vertex (Reynolds’ transport theorem over the cell’s faces through it); on a rule-(a) piece they are the bound’s, and at a kink of d lying on a cell face the Hessian is the one-sided limit for the vertex moving into the cell. A split leaves the band’s sum of J unchanged up to rounding and rule (a). Measured (mac-mini, 2026-10-12) against the Python on the 1020 stored band cells of five cases and 21160 random band cells: J agrees to 1.4e-12 relative (the problem’s own conditioning: the Python’s spread over the 24 corner orders of the same cells is as large), gradient and Hessian to 7e-11 (two of 4800 corner evaluations at 6e-6 in the Hessian, a cell face on an input edge where both are 2e-6 off the one-sided finite difference). Cost per cell: value 2.4-6 us, value with gradient and Hessian 3-43 us, against the corner bound’s 0.5-1 us. Cube outward, 3 turns, serial, without refinement, against “corner_bound”, the config otherwise the same (measured 2026-10-12 on ee18e19a1d, before held positions were picked by E): turns took 26.7 / 7.5 / 6.2 s against 6.7 / 2.9 / 2.5 s (smoothing 30.6 s against 5.3 s, mean Newton iterations 2.09 against 2.16); no smoothing pass raised E; every split changed the band term by at most 8e-15 relative (the corner bound’s: up to 1.3e-3, the bound tightening), the in-loop check that the integral is exact; max AMIPS 16 against 39, the ring measure’s max 12.8 against 5.1 bars (worst vertices near the cube’s corners). “front_flux” (2026-10-13): the same J_t for every cell the operations, the veto and the energy read (“exact“‘s value; a cell’s part of the front form is J_t by the divergence theorem), and the front smoother’s band term in the front form: per input feature (face, edge, vertex) a field G with div G = d - target_distance, tangent to the feature’s region planes and 0 on the input (face (d^2/2 - delta d) n, edge (d/3 - delta/2)(x - its projection on the edge line), vertex (d/4 - delta/3)(x - v)), so the band integral is the flux of G through the band’s boundary faces plus, per cell, the jump D_t of G.n across the bisectors (where two features are nearest) inside it. The vertex’s band term is the flux through the band’s boundary faces through it plus D_t of its flagged band cells, divided by target_distance: “exact“‘s term up to a constant in the vertex position (the flux through the faces not holding it). Its gradient is the sum over those faces of n int_f (d - delta) phi dA (phi the vertex’s hat function; Reynolds’ transport theorem), its one-vertex Hessian the derivative of that, with no D_t term (d is Lipschitz). D_t is computed only for a cell flagged from the input alone: the overlaps of two features’ regions within 2 target_distance of the input (and on the offset side of both), in a box tree; a cell whose bound on d exceeds that reach is flagged too; a false flag gives D_t = 0 exactly. Each piece of a face or cell is labelled with its nearest feature exactly (the exact range of the difference of squared distances, a quadratic, over the piece; planar bisectors split it); a curved bisector (face-edge, face-vertex, edge-vertex, skew edges) that changes sign on a piece is an error: the run stops with the feature pair and the position, as no approximation is made (“exact” bounds such a piece, rule (a)). The offset side as “exact”: only the parts on the offset side of the input count. The exit test is unchanged. Measured (laptop, 2026-10-14, cube outward, target 1e-2, bar 1e-4, serial): the first smoothing pass matches “exact” to rounding (same accepted and refused moves; the energy after each turn-1 group equal to 10 digits); front_flux exited resolved at turn 13 in 603 s, “exact” ran its 15 turns unresolved in 1691 s (sharing the machine for its first 8 turns); one evaluation of the band part of a front vertex (value, gradient, Hessian), median / p90 over the front vertices of three band states (turn 1 after the split, a stored band, the last turn): corner_bound 6-7 / 11-17 us, “exact” 55-238 / 424-809 us, front_flux 25-150 / 193-508 us; the value alone, front_flux 25-65 us against “exact” 19-32 us (the edge flux needs a weighted face moment of the line distance, which only the derivative-grade series computes). Most of it is the closed forms of the edge and vertex distances over the face parts near input edges (the near-parallel series); the labelling is 6-7 us. The cube outward has no region overlaps on its offset side: no cell is flagged and no D_t is evaluated. “corner_bound” is the default.

    Default: 'corner_bound'

    Options: ['corner_bound', 'exact', 'front_flux']

    /EXPERIMENTAL_settle_refinement (bool) 

    /EXPERIMENTAL_settle_refinement

    Description

    EXPERIMENTAL (2026-10-09), 3D. Refinement and exit wait for the front to settle, then judge every front face by its distance from the level set d = target_distance. Each turn, after the energy criterion: dE = E_prev - E, E the offset energy – the band term of the energy (see offset_amips_weight) summed over the band cells, without the AMIPS term, which changes wherever the mesh is improved whether the front moves or not (measured 2026-10-14, serial, Geneva settings: splits raised the whole energy through its AMIPS term by 0.7-3.6 b per turn on the cube outward) – at the end of the turn, and E_prev at the end of the previous turn (turn 1: just before its first operation group); the bar energy b = front_conv^2 * A / (2 * target_distance), A the total area of the front faces: the excess of the offset term for a front of area A lying front_conv beyond the level set (per unit area the integral of s / target_distance over s from 0 to front_conv). The turn is settled when dE < b. An unsettled turn refines nothing and does not exit: the front is still moving, and a face judged now is judged where the front passes, not where it comes to rest. On a settled turn a front face f is marked when max(inside_f, outside_f) > front_conv, with inside_f = target_distance - min over f of d (exact: the min over input triangles P of the triangle-to-triangle distance) and outside_f = (max over f of d) - target_distance, exact up to rounding (EXPERIMENTAL_settle_mark “max”): f is cut by the input’s nearest-feature regions (face prisms, edge wedges, vertex cones) as the exact band integral cuts a cell (EXPERIMENTAL_band_volume_rule); on a piece where one feature’s distance is d, d is convex and its max is at a vertex of the piece; on a piece whose region boundaries are curved (“rule (a)”) the min over its features of each one’s max is used, an upper bound. The former outside_f, the min over input triangles P of the max of d_P over f’s three corners, is one triangle’s convex distance and overshoots by about s^2 / (2 target_distance) where f straddles a coplanar input edge by s: measured on the cube outward (settle_mark “max”, exact rule), turn 28, all 8 faces it marked read 1.06-1.26 bars by it and -0.016 to +0.020 bars by the exact max; they alone blocked the exit at that turn. Under settle_mark “rms” and “vertex” outside_f is only logged and is still the former bound. Every marked face has the sizing scalar halved at its three corners (down to the sizing floor); a marked face with all three corners at the floor cannot be refined, is counted and warned about, and blocks the exit like every marked face. Exit: settled and no face marked. The run then ends as on the ordinary exit (the frozen-front final pass when max AMIPS >= stop_energy), and this exit is the front half of the verdict. The energy criterion’s own refinement (its refinable faces or vertices) and its exit test do not act; its turn line is still logged. One [settle] line per turn. true is the default; false = the energy criterion’s refinement and exit.

    Default: True

    /EXPERIMENTAL_settle_mark (string) 

    /EXPERIMENTAL_settle_mark

    Description

    EXPERIMENTAL (2026-10-09), with EXPERIMENTAL_settle_refinement: which test marks a front face on a settled turn (the settle, the halving and the exit are unchanged). “max”: the face’s largest distance from the level set, max(inside_f, outside_f), exceeds front_conv (exact up to rounding, see EXPERIMENTAL_settle_refinement). “rms”: the face’s share of the offset term’s excess exceeds the bar energy of its area. The share, to first order in d - target_distance (divergence theorem on G = (½)(d - delta)^2 grad d; exact for any band shape, folds included, up to the curvature and medial-axis term), is X_f = (½ delta) int_f (d - delta)^2 cos(theta) dA, theta the angle between the face’s normal (pointing out of the band) and grad d, signed; the bar energy of the face is front_conv^2 area(f) / (2 delta). So f is marked when the mean over f of (d - delta)^2 cos(theta) exceeds front_conv^2. The mean is taken by the 3-edge-midpoint rule (weights ⅓), exact for quadratic integrands, so exact over a face whose points all have one input face’s interior as nearest feature (d affine, grad d constant). Near an input edge or vertex (d curved) it is an approximation. Across a ridge of d (the medial axis, where two input faces are equally near: the inward offset of a convex edge, the outward offset of a concave one) it can miss the face’s excess entirely: measured on the prism inward (2026-10-09), one face read 0.24 bar by this rule and 7.46 bars over a 91-point grid. A face along grad d (cos theta near 0) or turned back (cos theta < 0) has a share near 0 or negative and is not marked; the max test catches such a face. “vertex”: a front vertex v is marked when |d(v) - target_distance| exceeds front_conv (d over all input triangles, exact at v), and its own sizing is halved; it says nothing about the points of a face between its corners. All three tests’ numbers are logged on every settled turn, whichever marks (under “rms” and “vertex” the max test’s outside_f is the former corner bound, see EXPERIMENTAL_settle_refinement). Read only under EXPERIMENTAL_settle_refinement. “vertex” is the default.

    /EXPERIMENTAL_gap_refinement (bool) 

    /EXPERIMENTAL_gap_refinement

    Description

    EXPERIMENTAL (2026-10-10), 3D, needs EXPERIMENTAL_settle_refinement. On a settled turn a band cell with a front corner is also refined (its four corners’ sizing halved) when md - d(centroid) > front_conv: md is the corner mean of the bounding triangle’s distance (the corner bound’s own min over input triangles, see EXPERIMENTAL_band_volume_rule), d(centroid) the exact distance at the cell’s centroid.     /offset_amips_weight (float) 

    /offset_amips_weight

    Description

    The weight w of AMIPS in the per-cell energy. 3D: THE energy E is the sum over the cells of tet_energy (TopoOffsetTetMesh::tet_energy()) = (w / stop_energy^3) vol AMIPS^3 (AMIPS against the cell’s rest shape for a plastic cell under use_rest_pose), plus for a band cell b = vol * min over the input triangles P of the mean over its four corners of (d_P - target_distance) / target_distance, d_P the distance to triangle P alone (EXPERIMENTAL_band_volume_rule “corner_bound”, the default; “exact” takes the cell’s closed-form integral of (d - target_distance) / target_distance); MAX_ENERGY where the engine cannot score the cell’s AMIPS. b is the cell’s part of the integral over the band of (d - target_distance) / target_distance, as an upper bound that no split raises (d_P is convex and d <= d_P). Both terms are volumes, so E converges under refinement; a cell at the stop energy costs about w vol in AMIPS. Every operation compares the SUM of tet_energy over the cells it changes, before against after: a collapse may not raise it (a tie passes); a swap – 3-2, 4-4, 5-6, the face swap, and the 4-4 / 5-6 case search and the face swap’s gate that pick and gate the cells it makes – must strictly lower it; a smoothing move may not raise it over the vertex’s ring; a split is judged only under EXPERIMENTAL_split_energy_gate. The engine’s own AMIPS^3 rules for collapses and swaps are off. The smoother minimises the vertex’s part of E: the AMIPS term over its ring and, unless an input envelope holds the vertex, the band term of its band cells. Needs one input region, an input complex of triangles only, and offset_field ‘euclidean’ (refused otherwise). Why the corner bound with the min over all triangles, and why a vertex held on the input carries no band term: see TopoOffsetTetMesh::band_cell_term() and smoothing_extra_energy(). DEFAULT 1, the weight the band-volume runs used (the eight-case suite of 2026-10-09 among them). The default before, 1e-4, was chosen 2026-09-30 for the energy this replaced (AMIPS^3 plus the front faces’ squared measures, compared by maxima); here it would make the AMIPS term 1e-10 vol AMIPS^3. 2D: the same weight multiplies AMIPS (the 2D engine’s cell quality) in tri_energy = w AMIPS + the offset terms of the front chords, and in the 2D front smoother.

    Default: 1.0

    Range: [0.0, inf]

    Description

    Log-only: after every operation pass and every smoothing pass, count the front vertices whose ring measure crossed the bar (from <= 1 to > 1, and back), plus new vertices already over it; inside the front smoother, classify each accepted move whose ring-measure crossing it caused as the moved vertex’s own or a front neighbour’s. Changes no result; costs an exit-measure evaluation per pass and a local one per front move. 2D and 3D.

    Default: False

    /use_rest_pose (bool) 

    /use_rest_pose

    Description

    3D. Which AMIPS the energy (see offset_amips_weight) uses for the cells outside the offset band and the input complex during the loop; the band and the complex are always measured against the regular tet. true: the plastic medium – each such cell’s AMIPS term is vol A^3 with A its AMIPS against its rest shape, stamped when the loop starts, after every smoothing pass (between passes and after the last, not before the first), and, in the operations, on every cell a split or a swap creates or a collapse changes, before that operation’s energy rule reads it; so every rule reads up-to-date rests, and a smoothing pass resists only what it moves itself. When an operation’s cells before and after are all plastic (no band or input-complex cell), its energy is exactly the same before and after (A = 3 everywhere, one total volume), which floating point does not reproduce (TopoOffsetTetMesh::plastic_tie()). The equality is taken instead: such a swap is refused outright, and such a collapse is not gated by the energy, only by the length gate, the inversion test and the other refusals. Logged per group as [plastic tie]. The rules (tet_energy()), the swap candidates and the smoother all read the same term. false (the default): the regular tet for every cell. Off in the final pass either way. Envelopes, either way: during the loop only the domain wall and the input complex’s boundary are held (envelope_size); every other region boundary is a tracked face nothing holds, and is held, as the loop left it, only in the frozen-front final pass. Replaces deform_others (removed 2026-10-13; 2D hard-wires its old default, false, until the 2D port).

    Default: False
